## Architecture Differences

### v4.5.x (3-Timeframe System)
```
M1 Chart (alignment check + crossover detection)
├─ TF2 (M4) - Medium-term alignment
└─ TF3 (M15) - Higher-term alignment

Entry Logic:
1. Check M1, TF2, TF3 all aligned
2. Detect M1 price crossover of M1 SMA
3. Enter trade (apply ADX flip if needed)
```

### v4.6.0 (4-Timeframe System)
```
M1 Chart (alignment check only)
├─ TF0 (M2-M6) - Entry trigger (crossover detection)
├─ TF1 (M7-M10) - Medium-term alignment
└─ TF2 (M15/M20/M30) - Higher-term alignment

Entry Logic:
1. Check M1, TF0, TF1, TF2 all aligned
2. Detect TF0 price crossover of TF0 SMA
3. Enter trade (apply ADX flip if needed)

Rationale: M1 too noisy → TF0 provides cleaner signals
```

## Hypothesis: Why v4.6.0 Failed

### Theory 1: Over-smoothing
Adding TF0 (M2-M6) as entry trigger may **delay entries too much**:
- v4.5.x: M1 crossover = immediate entry
- v4.6.0: TF0 (M4) crossover = delayed 4 minutes
- Result: Missed optimal entry points

### Theory 2: Alignment Constraint Too Strict
v4.6.0 requires **4 timeframes aligned** (M1 + TF0 + TF1 + TF2) vs v4.5.x's **3 timeframes** (M1 + TF2 + TF3):
- More alignment checks = fewer trade opportunities
- Stricter filter = missed profitable setups

### Theory 3: TF0 Doesn't Filter Noise Effectively
The assumption that TF0 (M2-M6) provides "cleaner" signals may be incorrect:
- M1 noise may contain profitable micro-trends
- TF0 may smooth out these opportunities

### Theory 4: v4.5.x Was Already Optimal
The original v4.5.x design was already well-optimized:
- M1 for entry detection is fast and responsive
- TF2 (M4) + TF3 (M15) provide adequate filtering
- Adding TF0 + TF1 adds complexity without benefit
